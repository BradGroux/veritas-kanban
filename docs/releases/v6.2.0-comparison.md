# Veritas Kanban 6.1.7 → 6.2.0 visual comparison

**Signed distribution candidate; upload and release readback remain separate.** All original views have current equivalents. Every new still was inspected, both original and new GIFs were played through complete cycles, and the new MP4 played to completion without an error. The original images are verified against retained manifests.

The original 6.1.7 capture used build `ed5094c6a5f9dd6958ceb952d8d018a40135bf33`, bundle `io.digitalmeld.veritas-kanban`, and packaged-app SHA-256 `a23df6443940aff4d9b5013b97ab753b986a63f3bb15dc0d3a8c6aaace866f94`. All fourteen maintained assets match the recovered capture manifest, and all ten task-mode images match their [retained manifest](../assets/v6.1.7/task-mode-audit/manifest.json). Original files remain unchanged.

Desktop maintained captures use 1700×760 content dimensions; mobile browser captures use 390×844. The original task-mode audit used a 1180×900 native window and included its frame and shadow. The current capture records 1180×900 window content without the original frame/shadow. The original task-mode fixture, “Prototype AI triage,” was blocked with failed-run history; the new “Prepare the release candidate” fixture is To Do with no run. Differences in readiness, run results and history reflect those fixture states and do not establish a behavioral improvement. New captures use macOS 15.7.9; the original maintained captures used macOS 15.7.9.

The [media capture contract](../design/DOCUMENTATION-MEDIA-CONTRACT.md) binds new images to the actual packaged candidate and checks original and committed file hashes. Visual review and full GIF playback are separate acceptance steps.

Candidate build: `0b5d65754735716edfd8ebe8ecb93633b70bfbc7`; whole-app SHA-256: `fab61cf2514475b2d872d8f041735ba3fe59bee54d80a6dcb9ccabe27de69fba`. All new media comes from this candidate except the explicitly labeled mobile browser views.

## Focused large-board comparison

### Board with 5,000 tasks

Both packages used the same synthetic task generator, 1360×900 content size and dark theme. The baseline was captured on the local macOS 26.6.2 host; the signed candidate was captured on the macOS 15.7.9 signing runner. Hardware and host conditions differ, so this is not a performance benchmark. The candidate scrolls the selected offscreen task into view after keyboard movement; the baseline retained the first rows. Card truncation remains deliberate. The image shows selection and layout; performance and persistence claims come from the separately recorded packaged journey.
