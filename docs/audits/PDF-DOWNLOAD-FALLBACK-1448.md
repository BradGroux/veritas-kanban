# PDF deliverables: download-only (#1448)

The maintainer chose downloadable PDF deliverables instead of inline PDF rendering. This supersedes the original request to repair the blank sandboxed viewer. The client no longer embeds PDFs or displays PDF zoom controls, including when an older server returns the legacy PDF content shape. It tells the user to download the file and open it in their preferred viewer; it does not launch files automatically.

The server keeps the existing PDF validation and the authenticated artifact source boundary. A valid PDF now returns `unsupported`, `renderer: "none"`, and no preview content. Quarantine, expiry, integrity, active-content and resource checks remain unchanged. Download authorization and the exact immutable artifact version still go through the existing download endpoint. No dependency or lockfile change is required.

Seven focused client tests and eight server tests passed. Web and server typechecks, changed-source lint, and both independent source review axes passed. Four browser PDF cases passed in both themes and normal/reduced motion, each at 1700×900 with 16px text and 1180×760/900×480 with 20px text. They verify download instructions, absent embedded viewers and zoom controls, reachable controls, filename, synthetic download completion, and opener restoration instead of asserting PDF rendering. Light/dark minimum-size captures were inspected. No file was opened automatically; launching the system viewer is a user action, not claimed by these tests. Rebuilt packaged-app verification remains required before closing this issue. The installed app and final documentation media have not been updated by this change.
