# Responsive overlay focus (#1445)

Settings retained the HTMLElement that opened it, but Header replaces that element at its compact breakpoint. Returning to desktop width created another button, so dismissal could not restore focus. The browser regression reproduced this at 1440×1000 → 620×650 → 1440×1000 before the fix.

Toolbar actions now have explicit logical focus keys. Overlay dismissal prefers the original usable element, resolves its current keyed replacement when needed, and uses visible Search when the action is absent in the compact toolbar. Disabled, hidden, disconnected, and inert targets are excluded. If another overlay remains open, restoration must stay inside the active overlay. This protects nested dismissal and command-palette handoffs. Unmarked non-toolbar openers keep their existing exact-element behavior.

Five browser checks cover Settings remount and compact fallback, nested confirmation dismissal, both New Task toolbar variants, and palette-to-Settings handoff after resizing. Existing discovery checks cover animated reopening and light/dark handoffs. All eight cases passed across the focused runs. Twelve overlay component tests pass; the nested portal test now uses real portals instead of the Mantine test environment that puts children beneath their inert parents. Web typecheck and changed-file lint pass. Specification and standards reviews found no actionable issues.

The unsigned macOS arm64 candidate built from this change also passed Settings, nested dismissal, New Task, and palette handoff checks in both themes in an isolated synthetic profile. The native window enforces a 1180px minimum width: the 620-CSS-pixel compact case was exercised at 200% zoom in a 1240×1000 content window, not by disabling that minimum. Returning to 1440×1000 at 100% zoom restores the current desktop action. Native window captures show visible Search focus after compact dismissal and focus inside Settings after handoff. Browser screenshot capture cropped the zoomed window, so visual evidence was recaptured through Electron's native window capture API.
